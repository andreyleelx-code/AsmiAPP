# Сортировщик картинок (Android)

Приложение подбирает картинки из выбранной папки **на телефоне** по текстовому запросу.
Анализ и поиск идут на самом телефоне, без ключей API и без облака. Интернет нужен только один раз,
чтобы скачать модели.

**Статус: шаги 1–3 из 9** (каркас, индексация, текстовый поиск). Голос, референсы и обучение на лайках впереди.

## Как получить APK

1. Создай на GitHub пустой репозиторий (например `photo-sorter`).
2. Загрузи в него всё содержимое этой папки (включая скрытую `.github`).
3. Открой вкладку **Actions**. Сборка `Build APK` запустится сама. Если нет, нажми **Run workflow**.
4. Через 3–6 минут открой завершённый запуск и скачай **Artifacts → photo-sorter-debug-apk**.
5. Распакуй zip, перекинь `app-debug.apk` на телефон и установи (разреши установку из неизвестных источников).

## Первый запуск на телефоне

1. Нажми **Выбрать папку** и укажи папку с картинками (вложенные папки тоже читаются).
2. Нажми **Скачать модель** (около 150 МБ, один раз, лучше по Wi-Fi).
3. Приложение само проанализирует картинки. Пока идёт анализ, экран не гаснет, приложение лучше не сворачивать.
   Для первой проверки положи в папку 50–100 картинок и посмотри, как быстро идёт.
4. Введи запрос, например «красивые пейзажи», и нажми **Найти**.
   Русские и корейские запросы автоматически переводятся на английский (языковой пакет ~30 МБ скачивается при первом таком поиске).

Если картинки добавятся в папку позже, нажми **Обновить**: проанализируются только новые.

## Как это работает

- **Модель:** CLIP ViT-B/32 (int8) через ONNX Runtime. Она превращает каждую картинку и каждый запрос в вектор из 512 чисел,
  близость векторов означает близость по смыслу. Векторы хранятся в базе SQLite на телефоне.
- **«Красивые выше»:** грубая оценка эстетики, сравнение картинки с фразами «красивая профессиональная фотография»
  и «некрасивое размытое фото». Это эвристика, её нужно настраивать на твоих картинках.
- **«Возможно подойдёт»:** картинки, похожие на лучшие результаты, но не попавшие в основную группу.

## Проверено при разработке

- Токенизатор CLIP на Kotlin даёт те же числа, что эталонная реализация (18 тестовых фраз, включая юникод).
- Сама модель проверена на примерах: еда находится по «food», города по «city street», оценка «красоты» падает на размытых и тёмных копиях.
- Проект собирается в APK (Gradle 8.14.3, JDK 21).
- **Не проверено на реальном телефоне:** скорость анализа, перевод запросов, чтение папки через системный выбор. Это первое, что нужно посмотреть.
